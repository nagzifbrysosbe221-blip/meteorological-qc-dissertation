Study Design and Implementation / Data foundation

Data collection and preparation

Read, copy or download the complete Python code ↓

The study used historical KNMI observations to compare methods for detecting gradual measurement bias and data-integrity faults. This section documents the selected data, how it was acquired and checked, and the limits of its use.

Recorded outcome. The saved datasets for 2021–2023 contained 52,560 hourly records across two stations, with a temperature and humidity value in every selected record. Checks supported their use for fitting, selection and validation. Historical station information remained incomplete, and the background readings were assumed normal rather than verified as fault-free.

Research purpose

Problem definition, objectives and success criteria

Weather readings can remain within ordinary limits while gradually becoming biased. Missing records, duplicate receipts and incorrect times create different integrity problems. The study therefore asked whether combining simple checks with residual monitoring would improve detection while keeping false alarms visible.

The dissertation research question

How effectively can a hybrid QC approach detect sensor drift and data integrity faults in meteorological time-series data, compared with a threshold-only baseline, while maintaining a low false alarm rate?

Aim. Design, implement and evaluate an explainable quality-control monitoring artefact. In the implemented comparison, historical temperature and humidity channels represented the measurement types; artificial gradual bias represented drift. A flagged observation does not by itself diagnose a physical sensor fault.

The five objectives and where to assess them

  1. Review the relevant literature. Establish the basis for weather-data quality control, drift detection and anomaly detection; see the Dissertation References.
  2. Design an explainable pipeline and reproducible experiments. Specify the data roles, checks, controlled cases and evidence records; see the four study periods.
  3. Implement preprocessing, integrity checks, drift detection and user-facing outputs. Follow the procedures and complete Python files on these study pages.
  4. Evaluate against a threshold-only baseline. Compare B0, R and H on the declared controlled cases and background observations; see final evaluation.
  5. Critically analyse limitations, sensitivity and improvement opportunities. Retain misses, false alarms, variable-specific limitations and all four evaluation passes; see Results and Evidence.

How success was assessed

The study judged the implemented comparison through evidence: whether the declared checks and traceable outputs were produced, which faults each configuration detected, which it missed, its false-alarm burden and coverage, and how findings changed under the prescribed sensitivity settings. Prediction-model eligibility and 2023 validation had their own documented checks; they are explained on their respective pages.

The research question seeks a low false-alarm rate, but the study did not establish an operationally acceptable alarm budget or a single overall pass mark. More detections alone do not establish success. The assessment considers detection together with false alarms, unavailable checks and the limits of the background truth.

Dissertation: Section 1.2 (research question and five objectives), Sections 3.4–3.6 (comparison and evaluation). The website presents the completed work within the original three main sections.

1 / Dataset scope and purpose

Data selected for the comparison

Hourly air temperature and relative humidity were obtained from the Royal Netherlands Meteorological Institute (KNMI). Temperature provides a continuous measurement and relative humidity a bounded percentage, allowing the study to examine contrasting variable behaviour. Pressure, rainfall and wind were outside the implemented comparison.

Target stationDe Bilt, station 260. The monitored records; controlled faults were later introduced into copies of these data.
Reference candidateSchiphol, station 240. Same-variable, same-hour observations supplied candidate reference information. Model suitability was assessed after acquisition.
MeasurementsAir temperature (T) and relative humidity (U), defined by KNMI at 1.50 m height.
Sampling scheduleOne expected record per station per hour, interpreted in UTC.
Early source periods2021 for fitting; 2022 for model selection and calibration; previously examined 2023 for validation.
Final source period2 January–31 December 2024 for final scoring, with 1 January as unscored context. Its separate intake followed the recorded final protocol.

The stations were observation sources, not instruments installed by the researcher. Their identifiers do not establish the continuity of individual physical sensors. Schiphol was a candidate comparison source; its availability alone did not establish a reliable reference.

2 / Collection and inventory

Recorded acquisition and dataset contents

The acquisition script made separate requests for 2021, 2022 and 2023 to KNMI’s hourly selection service. Each request specified stations 240:260, variables T:U, and the year’s source dates and hours. The returned text contained five comma-separated fields.

  1. Requested the specified records. The early years were retrieved separately, allowing each response to be associated with its request and intended role.
  2. Preserved each response. Original bytes were saved without replacement. Retrieval details, file size and a SHA-256 file fingerprint were recorded alongside the response. This fingerprint allows later checks for any change to the saved file.
  3. Prepared records for analysis. Station, time and measurement values were read from each source row. The original text and record identifiers were retained so each prepared record could be traced back to its source.
  4. Checked the selected periods. A separately implemented file-reading check compared the saved originals with the prepared records, unit conversions and year assignments.

3 / Fields and interpretation

Data preparation and transformation

Purpose. Convert the source representation into usable analysis records while keeping each record traceable. Preparation changes units and structure; it does not make a suspicious reading normal.

The response columns were STN, YYYYMMDD, HH, T, U. The implementation converted their representation while preserving the original values and identity of each record.

FieldMeaningImplemented treatment
STNStation identifier260 identifies De Bilt; 240 identifies Schiphol. The source token was retained.
YYYYMMDDOriginal source dateDetermined period membership before timestamp conversion or later fault injection.
HHSource hour 1–24Hour 24 became 00:00 UTC on the following date. The original source date remained unchanged.
TTemperature in tenths of °CFinite values were divided by ten. Zero remained a value; a blank remained missing.
URelative humidity in percentValues remained in percent. U was used for humidity; RH denotes precipitation in this source.

Boundary treatment

A source record dated 31 December 2021 with hour 24 is displayed as 1 January 2022 at 00:00 UTC, but remains assigned to the 2021 source period. A separate returned record with an original source date of 1 January 2022 is excluded from the selected 2021 view. This distinction prevents timestamp conversion from changing the intended data roles.

4 / Checks and preservation

Data cleaning: checks and preservation

Purpose. Identify missing values, duplicates, invalid timestamps and other inconsistencies, then record how they were handled. In this quality-control study, automatic imputation, outlier removal or silent repair could erase the conditions being evaluated. Raw records and diagnostic states were therefore preserved.

The early-data audit used a separately implemented file reader (parser), independent of the one used by the monitoring system. It checked all returned records against the derived views, including units, station identities and source-year boundaries. The saved audit records success across the three snapshots.

The audit was independent of the implementation’s parser and detector; it was not an independent human scientific review. The acceptance record also retained incomplete station-history coverage and an assumed-normal background. No independently substantiated early numeric exclusions were identified; this does not establish that the background contained no faults.

Missing cells, absent hourly rows, duplicates and invalid timestamps remained distinct conditions in the implementation. Raw evidence was not silently repaired to make a record appear valid. Later artificial faults were applied to scenario copies, leaving the source snapshots intact.

5 / Limitations

What this data foundation supports

The preserved snapshots provide a fixed basis for comparing monitoring configurations under the stated data roles. Several qualifications remain relevant when assessing the later results.

  • Archive processing. KNMI may have checked, corrected or filled observations before release. Replaying this archive cannot reconstruct the original live stream.
  • Uncertain background truth. The returned fields contained no per-observation quality flag. Uninjected values were treated as assumed normal, not certified fault-free.
  • Station and reference uncertainty. Station-history coverage was incomplete. Station identifiers do not establish individual sensor continuity, and shared weather or reference errors may affect prediction.
  • Prior exposure. The 2023 validation data had already been examined. They are not described as a previously unseen validation set.
  • Bounded public evidence. This site contains the collection summary, implementation and saved results. Original raw snapshots and complete execution records remain in the separate research archive; the public package does not establish full-study reproduction.

Sources: KNMI archive qualifications; assessment and reproduction scope. Dissertation: Section 3.7 and Appendix D4.

"""Save dated KNMI responses without overwriting previous snapshots."""

import argparse
import json
import urllib.error
import urllib.parse
import urllib.request
from datetime import datetime, timezone

from records import ROOT, code_identity, digest, save_json, settings, utc_now

DOCUMENTS = {
    "script-access": "https://www.knmi.nl/kennis-en-datacentrum/achtergrond/data-ophalen-vanuit-een-script",
    "hourly-archive": "https://www.knmi.nl/nederland-nu/klimatologie/uurgegevens",
    "field-selection": "https://www.daggegevens.knmi.nl/klimatologie/uurgegevens",
    "copyright": "https://www.knmi.nl/copyright",
}


def early_parameters(year):
    if year not in (2021, 2022, 2023):
        raise ValueError("Only 2021-2023 acquisition is implemented; final intake is locked.")
    return {"stns": "240:260", "vars": "T:U", "start": f"{year}010101",
            "end": f"{year}123124"}


def download(url, params, directory, name):
    directory.mkdir(parents=True, exist_ok=False)
    body = urllib.parse.urlencode(params).encode("ascii") if params else None
    request = urllib.request.Request(url, data=body, headers={
        "User-Agent": "Dissertation-QC-data-foundation/0.1 (academic research)",
        "Accept-Encoding": "identity",
    })
    record = {"started_utc": utc_now(), "url": url, "parameters": params,
              "method": request.get_method(), "code": code_identity()}
    try:
        with urllib.request.urlopen(request, timeout=60) as response:
            payload = response.read()
            record.update(status=response.status, resolved_url=response.url,
                          headers={k: v for k, v in response.headers.items()
                                   if k.lower() in ("content-type", "content-length", "date",
                                                    "etag", "last-modified", "content-encoding")})
        raw = directory / name
        with raw.open("xb") as stream:
            stream.write(payload)
        record.update(finished_utc=utc_now(), bytes=len(payload), sha256=digest(payload),
                      raw_path=str(raw.relative_to(ROOT)), outcome="downloaded_not_yet_accepted")
    except Exception as error:
        record.update(finished_utc=utc_now(), outcome="failed", error=repr(error))
        save_json(directory / "manifest.json", record)
        raise
    save_json(directory / "manifest.json", record)
    return record


def main():
    parser = argparse.ArgumentParser(description=__doc__)
    parser.add_argument("kind", choices=["documentation", "early"])
    parser.add_argument("--year", type=int, choices=[2021, 2022, 2023])
    args = parser.parse_args()
    stamp = datetime.now(timezone.utc).strftime("%Y%m%dT%H%M%S%fZ")
    if args.kind == "documentation":
        for name, url in DOCUMENTS.items():
            result = download(url, None, ROOT / "data" / "source-docs" / stamp / name,
                              "response.html")
            print(json.dumps({k: result[k] for k in ("raw_path", "bytes", "sha256")}))
    else:
        if args.year is None:
            parser.error("early requires --year")
        result = download(settings()["source_url"], early_parameters(args.year),
                          ROOT / "data" / "raw" / f"knmi-{args.year}-{stamp}", "response.txt")
        print(json.dumps({k: result[k] for k in ("raw_path", "bytes", "sha256")}))


if __name__ == "__main__":
    main()
